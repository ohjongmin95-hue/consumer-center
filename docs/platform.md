# SOBORU 플랫폼 (한큐 + 소보루 비즈)

소비자제보센터 홈페이지와 분리된 별도 서비스예요. 같은 서버, 같은 저장소를 쓰지만 DB·주소·서비스가 따로예요.

| 주소 | 서비스 | 누가 |
|---|---|---|
| `hanq.consumerjebo.co.kr` | 한큐 | 소비자: 어느 기업이든 접수, 진행 확인, 해결 여부 응답 |
| `business.consumerjebo.co.kr` | 소보루 비즈 | 입점 기업: 홈(바로가기·승인 요청·최근 요청), 승인 요청, 전체 요청(검색), 자동 처리, 통계, 설정 |
| `business.consumerjebo.co.kr/ops` | 운영 | 센터: 기업 가입 승인, 비입점 기업 요청 처리 |

소비자 서비스 이름은 기본값 `한큐`이고, `/etc/soboru-platform.env`의 `CONSUMER_NAME`으로 바꿀 수 있어요.

코드: `platform_app/` (`hanq.py`가 실행 진입점, `core.py` 공통, `consumer.py` 소비자, `business.py` 기업·운영). 테스트: `tests/test_platform.py`.

## 처리 흐름

1. 소비자가 기업 → 유형 → 사유(버튼) → 연락처 순서로 접수 (한 화면에 질문 하나). 유형마다 묻는 말과 사유 버튼이 달라요. 버튼만 골라도 접수되고, 요약과 원하는 처리는 유형·사유로 채워요(제품 불량·기타만 원하는 처리를 물어요). 주문 취소·변경은 주문번호가 꼭 있어야 하고, 주문 변경·기타는 내용도 적어야 해요. 칸도 유형마다 필요한 것만 보여요(`core.FIELDS`): 배송 조회·주문 취소는 사유 버튼과 주문번호만, 제품 불량은 사진과 메모만.
   - 배송 조회는 요청을 만들기 전에 고객이 택배사와 송장번호로 바로 조회해요(`/track`, 스마트택배 무료 조회 키 필요, 조회 내용은 저장하지 않고 받는 분 정보는 보여 주지 않음). 키가 없거나 지원하지 않는 택배사면 택배사 홈페이지로 안내해요.
   - 유형: 배송 조회, 주문 취소, 주문 변경, 교환, 반품·환불, 제품 불량, 고객 응대, 기타. 주문 취소·주문 변경은 자동 처리하지 않고 사장님이 확인해요 (주문 취소는 환불 계좌 등록 가능).
2. **입점 기업 + 전달 동의**: 기업 화면으로 바로 전달, 답변 목표일 2일
   - 그 유형의 자동 처리를 켜 둔 기업이면 즉시 추천 조치 실행 + 답변
   - 아니면 승인 카드로 올라감: 승인(추천 조치 실행 + 답변) / 보류 / 자료 요청
   - 보상: 자동 처리 화면에서 유형별 보상(예: 적립금 3,000원)을 정해 두면 그 유형 요청마다 추천하고, 사장님이 고치거나 승인해야 고객에게 알림이 가요. 자동으로 주지는 않아요. 불량·배송·응대 요청은 정해 둔 보상이 없어도 직접 적어 줄 수 있어요.
3. **비입점 기업**: 운영 화면에서 공식 연락처로 전달 시도 기록 → 회신 기록 또는 회신 없음(피해구제 안내)
4. 소비자는 휴대폰 번호 + 조회 비밀번호로 어느 기기에서든 확인, 답변 후 해결됐어요 / 아직이에요
5. 미해결이거나 답변 목표일이 지나면 1372·한국소비자원 피해구제 안내

## 서버에 설치

1. 가비아 DNS에서 `hanq`, `business` 두 호스트를 consumerjebo.co.kr과 같은 서버 IP로 연결 (A 레코드)
2. 최신 코드 받기: `sudo bash /opt/soboru/app/deploy/update.sh` (main에 합쳐진 뒤)
3. 설치: `sudo bash /opt/soboru/app/deploy/platform-setup.sh hanq.consumerjebo.co.kr business.consumerjebo.co.kr 이메일`
   - 운영 화면 비밀번호를 물어봐요 (12자 이상)
   - DNS가 반영돼 있으면 HTTPS까지 자동 설정, 아니면 반영 뒤 같은 명령을 다시 실행
4. 설정 파일 `/etc/soboru-platform.env`: 메일 알림(SMTP), `PLATFORM_MODE=live`(시범 운영 띠 끄기)
5. 이후 업데이트는 기존과 같이 `update.sh` 한 번이면 두 서비스 모두 다시 시작돼요
   - 업데이트 전: 서버에서 직접 고친 내용은 `/root/soboru-before-update-날짜/`에 보관하고(git stash에도 남김), DB를 `/var/lib/soboru-platform/backups/pre-update-*.sqlite3`로 백업해요 (최근 10개).
   - 업데이트 뒤 소보루 CS가 200으로 응답하지 않으면 바로 전 버전으로 자동으로 되돌려요. 직접 되돌리려면 `sudo bash /opt/soboru/app/deploy/rollback.sh`.
   - 배포 전 점검: `sudo bash /opt/soboru/app/deploy/preview.sh [PDF 경로]` 는 새 코드를 /tmp에 따로 받아 운영 DB 복사본으로 기존 화면, 실제 AI 상담(여러 번 이어지는 대화, 환불 요청 담당자 연결), PDF 추출을 돌려 봐요. 운영 코드·DB는 건드리지 않아요.
   - 서버 상태가 이상하면 `sudo bash /opt/soboru/app/deploy/diagnose.sh` 로 진단 파일을 만들어요.

## 기업 CS 도구

- **법 기준·응대 가이드**: 조문은 `platform_app/law_texts.json`에서만 보여 줘요. 국가법령정보센터 원문 미러(github.com/legalize-kr/legalize-kr)에서 `law_extract.py`로 글자 그대로 뽑은 것이라 손으로 고치지 않아요. 법이 바뀌면 원문을 다시 받아 스크립트를 돌려요. 품목별 소비자분쟁해결기준과 소비자기본법 시행령 별표 1은 원문을 담지 못해 공식 링크로만 안내해요.
- **AI 답변의 법령 근거**: 상담창 AI와 제보 법률 안내 초안은 `platform_app/law_corpus.json`(화장품법·약관법·표시광고법·민법·전자상거래법과 시행령·식품표시광고법·식품위생법·소비자기본법·소비자분쟁해결기준 고시 본문, 찾기 쉬운 생활법령정보 인터넷 쇼핑 해설)에서 질문에 맞는 조문을 찾아(`law_corpus.py`) 그 원문만 근거로 답해요. 법률 질문이 분명하면 상담창은 인터넷 검색을 쓰지 않아요. JSON은 국가법령정보센터 PDF를 글자로 뽑은 파일을 `python platform_app/law_corpus_build.py <원문.txt> platform_app/law_corpus.json`으로 조문 단위로 나눈 것이라 손으로 고치지 않아요. 분쟁해결기준의 품목별 별표는 들어 있지 않아요.
- **AI 키**: 모든 AI 기능(상담창, 답변 초안, PDF 상품 추출)은 `platform_app/ai.py` 한곳을 거쳐요. `OPENAI_API_KEY`가 있으면 OpenAI를 써요. 기본 모델은 GPT-6 Luna예요. 평소 문의는 낮은 추론(low), 분쟁·불량 책임 판단·강한 불만·반복 문의는 높은 추론(high)으로 답해요(`chatbot.level`, 낮은 추론의 AI가 `deep`이라고 하면 다시 높은 추론). 높은 추론이 실패하거나 `sure=false`면 운영 > AI 모델에서 켠 경우에만 GPT-6.1 Sol을 불러요(처음엔 꺼짐). 예전 gpt-4.1-mini는 쓰지 않아요. 모두 실패하면 기본 안내로 답하거나 사장님 승인으로 넘겨요. 운영 > AI 모델의 연결 시험으로 실제 API가 받는지, 같은 질문 비교로 일반·고추론 답을 확인해요. 모든 호출은 `ai_calls`에 모델·추론 수준·토큰·추정 비용·응답시간·결과(보냄·답함·사장님께·다시 물음)로 남고, 같은 화면에서 일반·고추론 Luna의 비용과 해결률을 비교해요. 환불·보상·취소를 해 주겠다고 약속하는 AI 답은 보내지 않고 사장님 승인으로 넘겨요. 키가 없고 `ANTHROPIC_API_KEY`만 있으면 Anthropic을 써요. `update.sh`는 AI 서비스 설정(/opt/soboru-cs/.env)에 키가 있으면 소보루 CS 설정에 복사해요. 키와 응답 내용은 로그에 남기지 않아요.
- **답변 초안**: AI 키가 있으면 AI가 회사 말투로, 없으면 유형별 기본 문구로 초안을 만들어요.
- **주문 장부** (사장님 화면 > 주문, 앱 > 주문 탭): 판매처 주문 엑셀을 CSV로 올리거나 직접 넣어요. 주문번호가 같으면 상태·송장만 고쳐 쓰고, 소보루에서 취소·반품·환불·교환으로 바꾼 상태는 다시 올려도 덮지 않아요. 고객 요청은 주문번호(없으면 같은 휴대폰 번호의 최근 주문)로 주문과 이어져 요청 화면에 주문 정보가 보여요. 구매자 정보는 그 기업 화면에서만 보이고, 기업 탈퇴 때와 마지막 수정 후 보관 기간이 지나면 지워져요. 판매처 API가 연결되면 같은 표에 채워 넣어요(`orders.py`).
- **요청 처리 = 주문 상태** : 주문번호가 맞는 요청을 처리하면 주문도 같이 바뀌어요. 취소 승인 → 취소, 반품 회수 확인 → 반품, 교환 상품 발송 → 교환, 환불 완료 → 환불, 송장 알리기 → 배송 중(송장도 저장). 이미 발송된 주문에 취소 요청이 오면 승인 버튼 위에 "반품으로 안내" 경고가 떠요. 휴대폰 번호로만 짐작한 주문은 바꾸지 않아요(`orders.sync_case`).
- **사장님 화면 배치** : 넓은 화면은 왼쪽 세로 메뉴(홈·요청·승인할 일·주문·배송·교환·반품·자동 처리·통계·응대 가이드·서비스 연동), 휴대폰은 위쪽 가로 메뉴. 홈은 오늘 숫자 4개, 승인할 요청(바로 승인 버튼), 실제 숫자로 만든 '소보루 브리핑'을 한 화면에 보여 줘요. 교환·반품은 새로 접수 → 회수 중 → 다음 처리 대기 → 처리 완료 단계로 묶고, 서비스 연동은 실제로 이어진 것과 준비 중인 것을 그대로 보여 줘요.
- **서비스 키 화면** (운영 > 서비스 키): 택배 조회 키와 AI 상담 키를 붙여 넣고 저장하면 바로 적용돼요. 서버 설정(/etc/soboru-platform.env)보다 먼저 쓰이고, 화면에는 끝 4자리만 보여요.
- **AI 상담창** (`platform_app/chatbot.py`): AI 키가 있으면 입점 기업 상담창에서 고객이 쓴 문장에 AI가 그 회사의 AI 상담 설정·안내 문구·자동 처리 규칙·반품 안내·상품정보(공개 항목)을 근거로 답해요. 가게만의 사실(가격·재고·배송·반품 정책)은 회사 정보에 있는 것만 말하고, 성분·사용법 같은 일반 지식은 AI가 아는 내용과 인터넷 검색으로 설명해요. 운영 > 서비스 키에 네이버 검색 Client ID·Secret(developers.naver.com, 사용 API '검색')이 있으면 AI가 필요할 때 네이버 웹문서·블로그를 검색하고(OpenAI 함수 호출), 없으면 OpenAI 자체 검색(Responses API `web_search`)을 써요. 검색이 안 되면 검색 없이 다시 물어요. 최근 대화 12개를 같이 보내 앞 대화를 이어 가고, 환불·취소·파손·강한 불만처럼 사람이 처리할 일이면 `handoff`와 담당자용 요약을 돌려줘요. 상담창은 '담당자에게 전달하기'로 요약과 고객이 쓴 말을 접수 내용에 넣어 기존 요청으로 이어 줘요. AI는 조회·환불·취소·배송지 변경을 할 수 없고, 했다고 말하지 않게 지시돼 있어요. 키가 없거나 실패하면 예전처럼 유형별 안내 문구로 답해요.
- **AI 상담 설정** (자동 처리 > AI 상담 설정, 표 `ai_profile`): 회사·브랜드 소개, 영업 시간, 배송 정책, 교환·반품·환불 규정, AI 상담 범위, 자주 묻는 질문, 담당자에게 넘길 때, 응대 지침. 기업마다 따로 저장되고 그 기업 상담에만 들어가요.
- **PDF 상품 등록** (`platform_app/product_pdf.py`, 자동 처리 > 상품정보 > 상품소개서 PDF로 올리기): pdftotext(poppler-utils, 한글은 poppler-data)로 글자를 읽어 AI가 상품을 여러 개 뽑고, 사장님이 검토 화면에서 고르고 고친 뒤 등록해요. 글자가 없는 PDF는 OpenAI에 PDF 그대로 보내요. 추출은 따로 돌고(웹 요청 30초 제한) 진행 상태는 `product_imports`에 둬요. 이름이 같은 상품은 기본으로 고르지 않고 '이미 있는 상품'으로 표시해요. PDF 글자에 없는 제품명·숫자는 '확인 필요'로 표시해요. CSV 올리기는 그대로예요.
- **내부 정보 분리**: 공급가·도매가·원가·마진·거래 조건은 AI가 처음부터 `internal`로 따로 뽑고, 코드(`guard`)가 고객용 칸에서 그런 말이나 내부 가격 숫자가 든 줄을 한 번 더 빼요. 내부 정보는 `product_private` 표에만 저장하고, 상담 AI(`chatbot.company_facts`)와 앱 API는 이 표를 읽지 않아요. 사장님 상품 화면에서만 보이고 고칠 수 있어요. 등록이 끝나면 추출 결과는 지워요.
- **상품정보**: 자동 처리 화면 아래(앱은 더보기 > 상품정보)에서 상품 이름·가격·재고·안내를 등록해요. 엑셀에서 CSV로 저장한 목록을 한꺼번에 올릴 수도 있어요 (첫 줄: 상품명, 가격, 재고, 안내).
- **택배 배송 추적 (스마트택배)**: 무료 조회 키 `SWEETTRACKER_T_KEY`가 있으면 송장을 넣을 때 한 번, 그 뒤로는 한 시간마다(cron, `notify_late.py`) 배송 완료 전 송장의 상태를 물어봐요. 유료 Trace API 키 `SWEETTRACKER_TIER`, `SWEETTRACKER_KEY`가 있으면 송장을 스마트택배에 등록하고, 배송 상태가 바뀔 때마다 `/hook/trace/<서명 토큰>`으로 알림을 받아 요청 기록에 남기고 고객에게 알려요(배송 출발·배송 완료). 반품 상품이 배송 완료되면 기업에 메일로 알려요. 배송 조회 요청에는 기업이 '송장번호로 답하기'로 바로 답할 수 있어요. 지원 택배사: 우체국·CJ대한통운·한진·로젠·롯데. 키가 없으면 송장번호와 택배사 조회 링크만 보여요.
- **반품 안내·송장**: 설정의 반품 주소·택배사(소개만, 연동 없음)가 승인 답변 끝에 붙고, 소비자가 송장번호를 입력하면 기업이 회수 확인을 눌러요.
- **정기 알림** (`notify_late.py`, 한 시간마다): 답변 지연, 불량 조기 경보(같은 상품 7일 3건·같은 유형 7일 5건, 하루 한 번), 월간 CS 리포트(매달 1일).
- **카카오 알림톡**: 솔라피 키와 `BIZ_KAKAO_TPL_NEW`(카카오 심사를 받은 템플릿 ID)를 넣으면 알림톡을 켠 기업에 새 요청을 보내요. 템플릿 변수는 `#{회사}`, `#{유형}`, `#{요약}`, `#{링크}`예요. 템플릿 예:
  ```
  [소보루 비즈] #{회사}에 새 요청이 들어왔어요.
  ■ 유형: #{유형}
  ■ 요약: #{요약}
  눌러서 확인하고 승인해 주세요.
  #{링크}
  ```
- **소비자 알림톡**: `CS_KAKAO_TPL_REPLY`(심사받은 템플릿 ID)를 넣으면 기업 답변·자료 요청·회수 확인·새 상품 발송·환불 완료 때 접수한 휴대폰으로도 알려요 (이메일은 적었을 때만). 개인정보 처리방침의 위탁 업체에 이름이 나오도록 `KAKAO_VENDOR`에 발송 대행사 법인명을 넣어 주세요. 템플릿 변수는 `#{회사}`, `#{내용}`, `#{접수번호}`, `#{링크}`예요. 템플릿 예:
  ```
  [소보루 비즈 고객센터] #{회사}의 소식이 있어요.
  ■ 내용: #{내용}
  ■ 접수번호: #{접수번호}
  눌러서 확인해 주세요.
  #{링크}
  ```
- **비밀번호 찾기**: 소비자는 휴대폰 번호와 접수 때 적은 이메일로 30분짜리 바로 열기 링크를, 기업은 로그인 이메일로 1시간짜리 재설정 링크를 받아요. 메일(SMTP) 설정이 있어야 동작하고, 링크는 `SECRET_KEY`로 서명하므로 서버에 `SECRET_KEY`가 고정돼 있어야 해요.
- **업종 비교**: 같은 업종 다른 기업이 3곳 이상일 때만 평균을 보여 줘요.
- **법·제도 소식**: 운영 화면 `/ops/news`에서 출처 주소와 함께 직접 올려요 (자동 수집 없음).
- **판매처 연결** (`/biz/connect/naver`, `/biz/connect/coupang`, 코드 `platform_app/shops.py`): 사장님이 스마트스토어(커머스API센터 애플리케이션 ID·시크릿)나 쿠팡(업체코드·Access Key·Secret Key)에서 직접 발급한 키를 넣어요. 소보루는 판매처와 따로 계약하지 않아요. 저장 전에 실제로 연결해 보고, 키는 `SECRET_KEY`로 암호화해 저장해요(`SECRET_KEY`가 바뀌면 키를 다시 넣어야 해요). 서버 cron이 10분마다 답변 안 한 문의를 요청으로, 주문을 주문 장부로 가져와요. 답변은 아직 판매처로 자동으로 올라가지 않아요. 두 판매처 모두 호출 서버 IP 등록이 필요해서, `update.sh`가 이 서버의 공인 IP를 `SERVER_IP`로 적어 두고 안내 화면에 보여 줘요. 쿠팡 키는 180일마다 다시 발급해야 해요.
- **카카오톡 채널 문의** (`/biz/connect/kakao`, 코드 `platform_app/kakao.py`): 사장님이 카카오 챗봇 관리자센터(chatbot.kakao.com)에서 봇을 만들고, 소보루가 준 스킬 주소(`/hook/kakao/<토큰>`)를 스킬로 넣어 폴백 블록에 잇고(봇 응답 '스킬데이터 사용'), 폴백 블록의 Callback 설정을 켜고, 채널을 연결해 배포해요. 소보루 쪽 키나 비용은 없어요. 스킬 요청엔 서명이 없어서 회사마다 다른 토큰으로만 받아요(DB엔 해시로 찾고, 화면에 다시 보여 주려고 `SECRET_KEY`로 암호화해 둬요. '주소 새로 만들기'를 누르면 예전 주소는 바로 안 들어요). 고객 말(`userRequest.utterance`)은 봇 사용자 키(`userRequest.user.id`)별로 인스타그램 DM처럼 진행 중인 요청에 이어 붙고, 없으면 채널 '카카오톡' 요청이 돼요. AI 자동 답변을 켰으면 카카오 5초 제한 때문에 `useCallback`으로 "잠시만 기다려 주세요"를 먼저 보내고, 같은 `chatbot.auto_reply`가 만든 답을 `userRequest.callbackUrl`(카카오 주소만)로 보내요. 콜백이 없으면 3.5초 안에 나온 만큼만 답해요. 환불·교환·취소·보상 결정은 다른 채널과 똑같이 사장님께 넘어가요. 챗봇은 고객이 말을 걸 때만 답할 수 있어서, 사장님 답·승인 답처럼 나중에 나온 말은 `kakao_out`에 담아 두고 그 고객이 다음에 말을 걸 때 앞 말풍선으로 전해요(상담 화면에 "고객이 카톡으로 다시 말을 걸면 전해져요"). 콜백을 못 보낸 답도 다음 말에 전해요. 말풍선은 1000자·3개까지예요. 카카오 Event API(먼저 보내기)는 쓰지 않아요.
- **네이버 톡톡 문의** (`/biz/connect/navertalk`, 코드 `platform_app/navertalk.py`): 톡톡 챗봇 API V1(github.com/navertalk/chatbot-api)을 써요. 사장님이 톡톡 파트너센터 → 개발자도구 → 챗봇API 설정에서 신청하고, 파트너 ID와 보내기 API 인증키(Authorization)를 소보루에 넣으면 회사별 주소(`/hook/navertalk/<토큰>`)가 나와요. 이 주소를 '이벤트 받을 URL'에 넣고 이벤트 send·open·leave·echo를 골라요. 이벤트엔 서명이 없어서 카카오처럼 회사마다 다른 토큰으로만 받아요(DB엔 해시로 찾고, 토큰과 인증키는 `SECRET_KEY`로 암호화해 둬요). `send` 이벤트의 `textContent.text`는 사용자 식별값(`user`)별로 인스타그램 DM처럼 진행 중인 요청에 이어 붙고, 없으면 채널 '네이버 톡톡' 요청이 돼요(사진 `imageContent`는 안내 문구만). 네이버 제한(연결 3초·읽기 5초) 때문에 바로 200을 주고, AI 답은 인스타그램과 같은 `chatbot.auto_reply_later`로 뒤에서 만들어요. 답(AI·사장님·승인 답)은 `https://gw.talk.naver.com/chatbot/v1/event`로만 보내요(헤더 `Authorization`, 본문 `{event:'send',user,textContent:{text}}`, 1만 자까지, 응답 `success`가 true여야 보낸 걸로 쳐요). 우리가 보낸 말이 돌아오는 `echo`와 open·leave·friend는 요청을 만들지 않아요. 인증키가 틀리면(401·403) '확인 필요'로 바꾸고 사장님께 한 번 알려요. 스마트스토어 톡톡 쇼핑챗봇·AI FAQ는 꺼야 하고, 연결마다 톡톡 계정 하나, 파트너센터 상담 상태는 저절로 안 바뀌어요.
